# Category：汽车

> 经 `category/index.md` 命中后才读。视觉调研只看 `creative-research` 节，进入具体 Stage 后只看该 Stage 的节。

## Stage Scope

| 这一块管什么 | 哪个环节用 | 写到哪 |
|---|---|---|
| 车是哪一款、用了什么料、有哪些功能、宣传口径是否合规 | `creative-research` | `category_profile`；产品参考登记表 |
| 走哪种故事原型、人和环境怎么变、卖点靠什么证明 | `anchors` | `video_creative_route`；`selling_point_binding`；`technique_plan` |
| 车怎么亮相、镜头怎么推进、怎么转场、声音与画面怎么对上 | `storyboard` | `generation_strategy_doc`；`generation_plan_unit` |
| 检查车型认不认得出、动得对不对、漆面与屏幕对不对 | 分镜里冻结，`visual-gen` 照做 | `constraints[kind=tvc_storyboard_plan_unit].execution_delta`；video work item 的 `prompt` |

## `creative-research`

### 补充事实

- 先弄清楚：哪一款、哪一年的车；燃油、混动还是纯电；厂家给这个颜色起的名字；这支片子到底要卖哪一两个点。
- 路线里真有车内镜头，才去整理座舱、仪表、大屏和内饰用料。
- 凡是涉及续航里程、百公里加速、刹停距离、碰撞评级、辅助驾驶的文案，把测试条件、出具方、年份、功能正式叫法一并记下。

### 参考与输出

- 用户给的外观图，逐张写清是从哪个方向拍的（车头、车尾、正侧、斜前、斜后、高处、贴地）以及图里哪些部位能让人认出这款车。
- 车内和屏幕的图按位置分开登记；缺了某个机位不必追着要。
- `category_profile` 里放：车型身份、颜色与用料、动力声音能写到什么程度、屏幕亮或灭、宣传语的出处。
- 风格候选要分工：有的负责交代地点，有的负责车在路上跑，有的负责天光与倒影，有的负责材料质感，有的负责车和风景的关系。五六张别都是差不多的整车美照；只补 Style Master 还空着的那一格，并在每张的 `contributes` 里写清它补了什么。
- 照片只能说明质感和运动趋势，推不出剪辑节奏。只有拿到参考视频时，才去数：开头几秒切了多少刀、密集快切在哪一段、平均一个镜头多长、画面朝哪个方向动、风景镜头和车镜头之间靠什么接。

## `anchors`

- 常用骨架：先看到人或世界原本的样子，再出现一个麻烦或向往，然后车登场、参与进来，用画面证明它做到了什么，人和环境因此变了，最后落回车和品牌。别一开场就是一串车头、车灯、轮圈、车标特写。
- 高端 / 品牌气质片，把 `brand_identity_reveal` 拆成五拍：风景或建筑先把品牌世界立起来；人物一个站姿、一个小动作说明他是谁；一个代表品牌精神的意象出现；只用剪影、质感或声音暗示车；最后整车清楚登场、品牌收尾。整体节制、细腻、情绪一点点往上走。零件特写不能冒充“暗示”。
- 借动物做意象，只能借它的气质和驾驶的情绪；通过同一姿态、同一视线方向、同一速度趋势或同一束光 / 一声响把它和车连一次，然后回到真车。动物种类和习性前后不能变；不能拿它代替卖点证明，更不能暗示车拥有动物的力量、速度或越野本领。
- 旅途型：出门 → 穿过城市 → 走进自然、在那里停下来；车是陪伴者，但片尾一定要看得到整车立在风景里。
- 科幻功能型：从险情或失控开始，车出手化解，镜头在车外和车内之间跳；关门那一下可以同时让画面、声音、情绪翻面。
- 材质微距是证明做工的一个段落，很少单独成片；用了就要接回整车、使用结果或品牌印象。
- 每个卖点写四件事：开始时什么状态、在车上做了什么、环境怎么回应、最后变成什么状态。座椅、空调、音响、大屏、车载冰箱、全景天窗都要挂在人物的需要上，不做配置表式罗列。
- 性能、安全、里程、辅助驾驶只写核实过的内容；微距、冷暖色、HUD、英雄镜头、动作接动作、速度感都只是技法库里的选项，看路线和已核实的事件再决定用不用。

## `storyboard`

分镜阶段把本节中适用的条目写成稳定标量，挂到对应单元扁平的 `constraints[kind=tvc_storyboard_plan_unit].execution_delta` 下。本节只负责冻结 Prompt 的输入、执行约束和结果检查，不写视频 work item；`prompt` 由视频生成阶段的 Planner 写，视频生成只认 capsule，不会再翻本卡。

### 生成规划增量

- 车的比例、颜色、镀铬件与大灯反光、能认出车型的部位，一律以核实过的 refs 为准。
- 外观、车内、屏幕、行驶画面各占多少，由用户方向决定，没有固定四段式或比例。
- 高端 / 品牌气质片在 `auto.luxury_reveal` 里按顺序写下那五拍情绪，不写死几秒、几个镜头。`product_tease` 只挑 refs 能证实的一两样东西延续情绪，比如剪影、漆面或玻璃上的倒影、一截灯带、车门开启、发动机或电机声、周围环境声；门的开法、灯的形状、车身比例、动力声都必须和真车一致。`hero_reveal` 必须让整台车清晰可辨（比例、颜色、识别部位），再用人物、空间、驾驶结果或品牌定版收住，不能停在认不出的局部。
- 用了动物意象，就在 `auto.symbolic_totem` 里记：是什么动物、代表什么、哪些特征每个镜头都不能变、它和车靠哪个动作 / 眼神 / 运动 / 光或声连起来、在哪一镜收回。这些比喻不能写进 `selling_point_proof`。
- 信息分三层给：先让人认出是哪款车，再让人看到做工，最后通过人的操作和结果让人感受到体验。
- 卖点单元要看得到因果：人的状态或需要 → 对车做了什么 → 环境怎么回应 → 人的结果；写进 `selling_point_proof`、`start_state`、`end_state`、`sub_shot_timeline`。
- 要表现车内外反差时，让关门同时切换空间、声音和情绪；门外的嘈杂、关门的闷响、门内的安静，分别写成 `sub_shot_timeline` 对应时间段里的 `sound=`。
- 任何匹配剪辑（动作、材质、光、颜色、形状、声音）前后都要有肉眼可见的延续；没有因果就别为了花哨加转场。
- 运动 / 科技 / 都市 / 强冲击类路线，开头可以用 3 到 6 个极短的小段制造冲击，素材从风景细节、路面飞驰、光影质感、车身局部、整车入画里挑；相邻两段至少换角度、换景别或换事件之一，写清 `cut_trigger`，每段大致 0.4 到 1.2 秒，最终以参考片节奏、音乐重音或真实物理动作为准。平台每次生成 5 或 10 秒的一条，快切只能写在同一条内部的 Sub-shot 时间线上。
- 讲安全、讲家庭、讲安静奢华、慢慢揭晓的路线不需要快切；用户原稿没有开头快切时，这条只能作为分镜内部建议，不能擅自增删或调换原稿事件。
- 行驶中的风景插镜只能靠运动方向、图形、材质、光的接力或声音反差衔接；时间、天气、色调、靠哪侧行驶、屏幕朝向、运动轴都要连得上。风景镜头要把速度、自由、安心、奢华或科技感递给相邻的车镜头，而不是纯粹点缀。
- 同一条内部的快切写进 Sub-shot 时间线；条与条之间只用分镜已定好的硬切或匹配剪辑，后期不再重新编排快切。
- 从零创作时可以从一个很小的细节开始，逐步放大到人、车、场景、天地，但最后一段必须落到能认出的整车或车内主画面和已确认的品牌信息；如果是沿用用户原稿，已确认的结尾不改。
- 驾驶动作符合投放地的交通习惯（方向盘在哪边、靠哪边开）；仪表和大屏写清是亮是灭。
- 声音按动力形式写：发动机、排气、电机啸叫、轮胎摩擦、风声。

### 参考与检查

- 需要特殊外观角度、某个车内位置或某块屏的镜头，从登记表里挑至多 3 张对应 refs。
- `vehicle_identity`、`paint_color`、`screen_state`、`driving_compliance`、`opening_rhythm`、`motion_direction`、`environment_insert_semantic_gap` 以及适用的宣传语合规检查，全部合并进一个 `auto.result_qc_boundary`，不单独建 `quality_checks`。

### Flat capsule 执行增量

- `auto.prompt_scope`：视频 Prompt 只能把分镜定好的路线、镜头、声画事件和参考路由翻译出来；执行时不能换故事原型，也不能加功能。
- `auto.luxury_reveal` 与（如有）`auto.symbolic_totem`：五拍结构、每拍露出多少车、意象的连续性原样带走；暗示段不能变成完整露车，动物段必须回到车。
- `auto.motion`：车头朝向、行驶侧、车轮转动、惯性、路面颠簸反馈，以及相邻两条的速度趋势都要对上；驾驶动作不超出核实过的能力和当地常识。
- `auto.material`：漆面、灯、玻璃、镀铬、真皮、缝线、屏幕的反光与透光要和 refs 一致；扬尘、烟、火花、动态模糊、HUD 都不能挡住认车的部位。
- `auto.result_qc_boundary`：包含上面那些检查，按需补 `material_match`、`powertrain_sound`、`product_recall`；它只规定视频生成阶段自检的范围，不保存检查结果。
