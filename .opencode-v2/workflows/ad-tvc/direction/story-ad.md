# Direction：剧情广告

> 经 `direction/index.md` 命中后才读。视觉调研只看 `creative-research` 节，进入具体 Stage 后只看该 Stage 的节。

## `creative-research`

- 剧情片靠观众入戏和人物（或主体）的转变来讲品牌主张。产品可以是点燃事件的东西、行动的工具、同伴、舞台或结果的证据，但不能到最后才硬贴上来，也不能替主角做决定。
- 往 `direction_profile` 里补：`narrative_promise`、`protagonist_or_subject`、`want`、`initial_state`、`inciting_incident`、`obstacle`、`choice`、`consequence`、`final_state`、`brand_role`、`emotion_arc`、`dialogue_policy`。`brand_role` 只能挑一个主角色。
- 用户给了脚本就照它来：谁先谁后、谁和谁什么关系、台词一字不改、信息揭晓顺序和结局都不动；发现缺了看得见的因果，只记下缺口，不偷偷改。
- 自己从头编时，故事只能有一根主干、一处核心冲突、一个关键抉择、一个品牌主张。人很少或没有人时，让主体的状态完成同样的“从 A 到 B”。
- 故事功能依次是：日常或目标 → 事件触发 → 阻碍与压力 → 行动或抉择 → 结果与品牌兑现。短片可以把相邻两步合并，但触发、抉择、看得见的结果一个都不能少。
- 开头直接进正在发生的动作、人物间的张力或一个视觉疑问，别用交代背景占掉前几秒；结尾要兑现开头的承诺，或者留下一个和品牌主张一致的清晰余味。

## `anchors`

- 路线要定死这些：谁是主角（或主体）、冲突是什么、品牌担什么角色、主场景在哪、用什么意象表示转折、转折前后画面各是什么样。真出路线 KV 时只画这些已确认的关系，不加配角、第二条矛盾或另一个结局。
- 主角要在多个镜头里保持同一张脸、而现有人物素材撑不住时才出模特卡；人物想要什么、做事的气质、关系、转折状态放在路线约束里，人物卡上不写剧情。
- 场景锚点卡只固定会反复出现的地方长什么样、一直存在的环境状态；某一刻的冲突、主角的决定、产品怎么动、结果如何，留给分镜和相应 refs。

## `storyboard`

- 分镜阶段把本节中适用的条目写成稳定标量，挂到对应单元扁平的 `constraints[kind=tvc_storyboard_plan_unit].execution_delta` 下。本节冻结的是 Prompt 的原料、执行时的限制、成片要查什么、坏了修多大范围，不写视频 work item；`prompt` 由视频生成阶段的 Planner 写，视频生成只认 capsule，不会再翻本卡。
- `narrative_stage` 按“铺垫 → 触发 → 加压 → 抉择 → 结果 / 兑现”排。每一段都得让至少一样东西变：主角想要的、人物之间的关系、面临的风险、观众知道的信息，或者事情的结果；没有变化的旁支、重复的反应镜头、只为氛围的空镜都删掉。
- 每个关键节点写清：开始是什么状态、人做了什么、遇到什么阻力、做完的结果、这个结果怎样推出下一个节点。旁白和台词不能代替缺失的动作或结果。
- 情绪靠动作、眼神、停顿、递东西、人与人之间的距离、环境的回应来表现；台词只说画面说不出来、且会改变信息 / 关系 / 决定 / 风险的话。
- 产品 / 品牌要在前因后果里真正干活，干的就是它被分配的那份：改变行动的条件、帮主角完成抉择、见证结果，或者把情绪主张变成一个具体物件。情绪最高点不插卖货台词，卖点通过人做了什么、最后变成什么来证明。
- 切点放在：一个动作完成、一条信息亮出、两人关系起变化，或者有东西自然挡住画面；矛盾升级时可以一步步靠近，解决后再把空间打开。用户要长镜头或固定视角时，就靠把动作拆成几段、不断变换构图来保持向前走的感觉。平台单条最长 10 秒，一个节点放不下就拆成相邻单元并写清衔接。
- 分镜文档完成前，按下面的“剧情结构 QC”逐条自查一次；结果不另存为 `constraints` 或平行 QC。任何一条不过，先改分镜，全部通过后视频生成才能开始 author。

### Flat capsule 执行增量

- `story_ad.execution`：Executor 逐单元对照已确认的节点、起止状态、原文台词和品牌角色来生成；不能为了画面炫技改掉抉择、结果或结局。
- `story_ad.result_qc_boundary`：视频生成唯一的结果自查项是 `silent_story_legible`、`beat_results_visible`、`performance_continuity`、`brand_payoff_visible`、`emotional_payoff_complete`。第一项的意思是：静音播放，观众也能看懂是谁、出了什么事、做了什么、结果如何；其余几项依次看动作结果是否可见、人物长相 / 状态 / 情绪是否连贯、品牌在因果里起没起作用、转折有没有兑现。它只圈定检查范围，不存结论或结果元数据。
- `story_ad.repair_policy`：计划没问题但画面跑偏时，只重做对应 `unit_id`，必要时连带重做衔接的相邻单元；如果是结构本身有漏洞，退回 Planner 修，而不是在查成片时现编情节。

## Planner 剧情结构 QC

- `causal_chain_complete`：起因、阻力、主角的行动或决定、后果四样齐全，前后两个节点之间有明白的因果。
- `character_arc_visible`：开头和结尾的状态，能从动作、关系或结果上看出不同，而不是靠旁白宣布。
- `brand_role_causal`：品牌 / 产品确实卷入了定好的那次行动或那个后果，删掉它故事会讲不通，而不是结尾可有可无的露出。
- `single_story_focus`：从头到尾只讲一件事、一个冲突、一次翻转，每个节点都在帮同一个主张说话。
- `dialogue_non_expository`：台词不复述画面上已经看到的东西，说出来之后，观众知道的、人物之间的、主角的决定或面临的风险至少有一样变了。
- `duration_feasible`：台词、动作、反应、品牌落点都算进了时长账，不需要演员超速表演，也没有看不见的跳步。
- 有一条没过就回去改路线或分镜；视频先别生成，更别指望 Executor 边跑边补故事。

## QC 所有权

- 上面这几条由 Planner 作为分镜文档能否收尾的前提；视频生成阶段对实际成片做唯一一次内部结果检查；media-agent 只按通过或不通过去推进、返修或把问题交回 Planner，不重新评判剧情。
- `execution_delta` 里只有检查范围，没有检查结论；检查本身不会多出新 Stage、新画布文档、新元数据或新的确认卡片。只有路线上的业务取舍才发 `question`，分镜和成片都不请用户审核。
