# Video Merge — 终剪合成

> **何时 Read**：多段视频都已生成，接下来要按顺序拼成片、保留或替换声音、按要求加字幕 / 文字叠层，并把成片放上画布时。

## Boundary

这里只处理不改变画面内容的剪辑工序：裁剪、按序拼接、缩放统一、保留或替换音轨、叠字幕或文字、转码、终混。想换角色、换地点、改表演、改风格或改镜头本身，那是重新生成视频的事，不归本卡。

## Assembly Contract

- 片段按分镜 / 脚本的顺序进入合成，用 `hub_merge_videos` 按列表顺序首尾相接。不要把几段内容重新揉成一个生成 prompt。
- 计划里的 Post stage 要写清：有序的片段逻辑引用、每一步操作（裁剪 / 拼接 / 转码 / 混音）、音频策略、最终输出 id；字幕或文字来源只在用户要求时出现。输出画幅和分辨率写在 `execution_locks`。
- 本配置没有可交互的时间线编辑器。用户说“先让我看看”“对一下顺序”时，先把拼好的版本放上画布请用户看，按反馈修改计划后再出终版；不要假装打开编辑器。
- 片段尺寸不一致时，先定 `scale_mode`：用户说了算；用户没说，就以项目锁定的画幅或第一段为准（`first`）。不允许把主体拉伸变形。
- 声音按计划 / 脚本处理：默认保留各片段自带的声音；换成旁白、叠加配乐或出静音版，都要有人明说才做。没要求就不额外配乐。
- 字幕和文字叠层默认不加。所选 workflow 在开场已和用户定下字幕策略的，按已确认处理。没有字幕需求时，只做拼接 / 裁剪 / 转码并保留原声，用户之后可以自己加字幕。需要字幕时按 `_shared/subtitle-pipeline.md` 走：先有 SRT 来源，再 `hub_subtitle_format`，最后用 `hub_ffmpeg` 以返回的 `absolute_path` 烧录。
- 旁白加配乐的终混用计划里固定的配乐音量；用户没要求就不做闪避或音量包络。
- 转场是用户或分镜定下的剪辑意图；没有指定就直接硬切，不自创花哨转场。
- `hub_ffmpeg` 只做拼接以外的事：单段裁剪、缩放、滤镜、混音、换音轨、叠字。它不接受拼接，拼接一律交给 `hub_merge_videos`。需要先逐段处理的，处理完再拼；拼完再做剩下的整片处理。
- 每个输入都取自当前 `runtime_refs` 对应的绝对路径；对话里的概述、节点上的显示名都不能当路径用。
- 用户点名要的字幕、标志、片头字卡、行动号召或必须一字不差的文字，都用后期叠加或静态卡片完成，不交给视频模型去写字。
- 输出文件名用项目语义名加 `_final`；工具返回的实际路径原样记录，不去改生成物的名字。

## Canvas Proof

- `hub_merge_videos` 只返回 `path`，不会自己上画布：拿到后调用 `hub_canvas_write_node(kind:"media")` 写入，返回的节点 id 才算交付。
- `hub_ffmpeg` 的正常输出会自动登记为画布资产，不要再写一次；如果它是在替换刚生成的临时片段，按工具说明传 `replace_node_id`。
- 终剪的路径和节点 id 通过 `hub_plan_update_stage_state` 记为 Post 工作项的输出。

## Checks

- 成片总时长和 brief 目标差得多，要给出解释；差得离谱就回到分镜重排。
- 多路输入的成片要保证音画等长；工具结果显示声音缺失或明显不同步时，停下来修正，不要继续往下做。
- 遇到少了某段、先后不清、尺寸怎么统一说法打架、声音怎么处理说法打架，先问用户或让 planner 调整计划，不要自己猜。

## Anti-patterns

- 拿到文件路径就当交付完成，没有对应的画布节点。
- 少片段、顺序没定或声画对不上时照样硬拼。
- 用户没要求就加字幕、转场或文字叠层，或无故重新编码改变原片时长。
- 用 `hub_ffmpeg` 做拼接。
