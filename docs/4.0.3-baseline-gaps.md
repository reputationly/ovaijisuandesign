# 缺基线的 3 屏：现状与所需改动

门禁按 `REFERENCE_MISSING` 跳过这 3 屏。它们**不是实现缺陷**，缺的是可复现的参照基线。

## 1. `project-assets` / `project-created`

### 卡在哪

这两屏的等待条件（`compare.mjs:2173`）要求 **ws-a 在 localStorage 里有一个已聚焦的会话标签**：

```js
const tabs = JSON.parse(localStorage.getItem("hilo:storage:global.workspaceSessionTabs") ?? "{}")["..."];
return !!tabs?.focusedSessionId && tabs.openedTabIds?.includes(tabs.focusedSessionId);
```

单屏录制或批次首屏时，工作区还没有任何创作页，于是：

```
[diag] ALIVE ws-a 会话焦点持久化: {"bodyText":"... 无创作页 ..."}
Error: 等待 ws-a 会话焦点持久化 超时
```

### 已验证失败过的三种做法

| 做法 | 结果 |
|---|---|
| 单屏 `ONLY=project-assets --record reference` | 超时 |
| 单屏 `ONLY=project-created --record reference` | 超时 |
| 批次 `ONLY=ws-a,project-assets,project-created` | 超时（ws-a 是首屏，仍无会话） |

### 为什么 37 屏全量跑能到这两屏

全量跑时前面的 `ws-*` 屏（尤其 `scenario:"chat"`）会创建并聚焦会话，
localStorage 里的 `workspaceSessionTabs` 就被填上了。

### 要做的事（二选一）

1. **在录制前 seed 一个会话标签**：用
   `Page.addScriptToEvaluateOnNewDocument` 预置
   `hilo:storage:global.workspaceSessionTabs`，使其含一个 `focusedSessionId`
   与对应的 `openedTabIds`。注意必须与夹具里真实存在的会话 id 一致，否则界面还是空。
2. **把这两屏放进取录批次的中后段**：批次里先跑一个会创建会话的 ws 屏。
   代价是那一屏也会被重录（本仓库已证明录制可复现，重录结果一致）。

**推荐 1**，因为它不依赖跑序。

## 2. `settings-platform`

**按规则排除**：这是本项目新增的「平台接入」设置页，4.0.3 参照里没有这一屏
（`REFERENCE_MISSING` 里已注明理由）。不需要基线。

`REFERENCE_MISSING` 目前还跳过了 `ws-a-v3` / `ws-a-v3-resource` / `ws-b-v3` ——
它们属 `V3_PAGES`，只在 `HILO_PROJECT_ARCHITECTURE=resource_v3` 时启用，
本次 4.0.3 验收不涉及。
