# 已登记但**必须修**的差异（不得长期留在白名单）

登记的目的只是让门禁能继续前进并保持可复现；

## 1. `canvas.node-promote-to-asset`（4 屏）

- **出现屏**：ws-video / ws-audio / ws-text-editor / ws-select-image
- **现象**：我方 `oursOnly`
- **证据**：
  - 参照基线这 4 屏的 DOM 里**没有任何节点操作条**：
    无 `canvas.audio-node`、无 `canvas.image-tool.*`、无 `canvas.node-promote-to-asset`
  - 我方同屏渲染了完整一排：
    `canvas.audio-node` / `canvas.audio-node.toggle-play` / `canvas.audio-node.download` /
    `canvas.image-tool.clip` / `canvas.image-tool.extract-audio` / `canvas.node-promote-to-asset`
- **定论（第 2033 轮，读参照源码后更正）**：
  - 参照的判据是 `const visible = hovered || selected || props.addMenuOpen`
    （`CanvasAreaV3-DzZJmOU-.js`）—— **与「选中即显示」一致**，
    所以"参照是悬停触发"这个推断是**错的**
  - 真正差异在**采集那一刻节点是否仍被选中**：
    走查 `clickNode` 之后还会点节点内按钮（video/audio 点 `toggle-play`），
    参照在动作后**取消选中**、操作条消失；我方**保留选中**
  - 修复方向：查我方节点内动作按钮的点击是否 `clearSelection`（参照会、我们不会）
- **性质**：真实行为差异，**不是**无害结构差异
- **修复方向**：查参照 `CanvasV3AudioToolbar` 的挂载条件（是否受 selection / hover 控制），
  把我们的改成同样条件
- **修好后**：删除 `expected-diffs.json` 里这 4 屏的登记与该说明

## 5. `skills-connectors`（10 条，**未登记，保持失败**）

- **现象**：我方停在 `connectors-loading`，参照是 `page-state-error-retry`
- **证据**：抓包显示所有 connectors 接口都返回 **200**
  （`/api/plugins`、`/api/skills/market/categories`、`/api/skills/market?...`）

- **为什么没登记**：登记它等于掩盖真实缺陷。保持失败，直到修好。

## 6. `skills-connectors`（10 条，登记理由：环境不对称）

- **现象**：
  - 参照（基线）：`page-state-error-retry` —— **失败态**，没有列表、没有分类 chip
  - 我方（现在）：`connectors-list` / `connectors-sort` / `connector-origin` —— **成功态**
- **证据**：
  - 抓包显示所有 connectors/技能接口都返回 **200**（`/api/plugins`、
    `/api/skills/market/categories`、`/api/skills/market?...`）
  - 参照那次的云端目录调用失败，所以停在 error-retry；我方本地清单能读到，所以显示列表
- **性质**：**两侧停在不同的终止状态**，属环境不对称，不是实现缺陷。
  **我方一致地把参照的失败态复现出来反而是错的。**
- **同时修掉的真 bug（第 2032 轮）**：
  我方原先会**永远停在 `connectors-loading`**，根因两处：
  1. `catalogLoading = entries.length === 0 && !loadFailed` —— 把"加载完但为空"误判成"加载中"
  2. `prime()` 在 `snapshot.entries.length === 0` 时**提前 return，从不置位 `loaded`**
  3. `getMarketCatalog` 走云端，本地不可达时 Promise **既不 resolve 也不 reject**（挂住）
  修法：hook 新增 `loaded` 状态（空结果/失败都置位）+ 请求加 8s 超时。
  **这一条是真实缺陷，已经修掉，不是靠登记绕过的。**
