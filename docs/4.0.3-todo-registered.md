## 1. `canvas.node-promote-to-asset`（4 屏）

- **现象**：我方 `oursOnly`
- **第 2039 轮定论（两次推断都被推翻，只保留实测）**：
  - **实测**：两侧的 `canvas.audio-node` / `canvas.image-tool.*` 等节点操作条**完全一致**，
    唯一差异就是 `canvas.node-promote-to-asset` 这一项
    → 「参照没有任何节点操作条」**错**，「参照悬停触发」**也错**

    （`canvas-area-v3.js:10809` / `:12562` / `:17320`、`ui-components.js:4409`）
    → 「我们无条件渲染」**也不成立**
- **真正的差异**：**动作可用性判定**。我们算出的 `promoteToAsset` 在 video / audio / text
  节点上可用，参照那边 `handlePromoteToAsset` 为空
- **下一步**：查 `actions.promoteToAsset` 的计算处，对比参照的 `handlePromoteToAsset`
  在哪些节点类型上为真

## 6. `skills-connectors`（10 条，登记理由：环境不对称）

- **现象**：
  - 参照（基线）：`page-state-error-retry` —— **失败态**，没有列表、没有分类 chip
  - 我方（现在）：`connectors-list` / `connectors-sort` / `connector-origin` —— **成功态**
- **证据**：
  - 抓包显示所有 connectors/技能接口都返回 **200**（`/api/plugins`、
    `/api/skills/market/categories`、`/api/skills/market?...`）
  - 参照那次的云端目录调用失败，所以停在 error-retry；我方本地清单能读到，所以显示列表
- **性质**：**两侧停在不同的终止状态**，属环境不对称，不是实现缺陷。
  **我方一致地把参照的失败态复现出来反而是错的。**
- **同时修掉的真 bug（第 2032 轮）**：
  我方原先会**永远停在 `connectors-loading`**，根因两处：
  1. `catalogLoading = entries.length === 0 && !loadFailed` —— 把"加载完但为空"误判成"加载中"
  2. `prime()` 在 `snapshot.entries.length === 0` 时**提前 return，从不置位 `loaded`**
  3. `getMarketCatalog` 走云端，本地不可达时 Promise **既不 resolve 也不 reject**（挂住）
  修法：hook 新增 `loaded` 状态（空结果/失败都置位）+ 请求加 8s 超时。
  **这一条是真实缺陷，已经修掉，不是靠登记绕过的。**
