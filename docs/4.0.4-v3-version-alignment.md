## 二、v3 门禁实测（按你的要求）

### 先补了 4.0.3 的 v3 基线

**`~/ov-golden-v3` 不能用**：它的 `mainScript` 是 `index-BBp4hclA.js`（**4.0.0**），
`referenceVersion` 还是 `null`（历史遗留 bug）。

**已新录 `~/ov-golden-v3-4.0.3`**：`referenceVersion: "4.0.3"`、
`mainScript: app://./assets/index-B3Ss5vz1.js`，2 屏（`ws-a-v3` / `ws-a-v3-resource`）。

### 还修了一个「空跑」问题

`REFERENCE_MISSING` 原本是**无条件跳过**，于是拿 v3 基线跑会「跳过两屏 + 退出码 0」——
**那是空跑，不是通过**。

**已改为「这份基线里确实缺这屏才跳过」**（`refBaselineAbsent`）：只要 GOLDEN 里有
`<屏>.png` 与三个通道的 json，就参与比较。

### 运行结果

```
运行目录：.probe/ui-compare/2026-10-23T13-44-29-818Z（打补丁后）
          与 /tmp 下的未打补丁对照运行
退出码：  1（**不是 0**）
```

| 屏 | 像素非AA | 未登记差异 | 新报错 |
|---|---|---|---|
| `ws-a-v3` | 3.545839% | 6 | 0 |
| `ws-a-v3-resource` | 3.098103% | 1 | 0 |

### 这些差异是什么（41 条 domDiff/屏，主要是元素错位）

```
$.length                     292 → 280（参照多 12 个节点）
$[15].attributes.aria-label  "MiniMax Design" → "蒜狸小助手"
$[16].attributes.role        "img" → <missing>
```

**两块原因，都跟 `<title>` 补丁无关：**

1. **主界面的品牌替换**（层 1）：参照 shell 的 `aria-label` 是 `MiniMax Design`，
   我们是 `蒜狸小助手`。这在 37 屏里是靠「有意差异遮罩」处理的，
   **v3 这两屏没有对应遮罩**。
2. **shell 里少一个 `img`**（参照在 `$[16]` 有个带 `aria-label` 的 img，我们没有）
   → 之后所有节点错位，撑出 39 条 `$.length` 连带差异。

### 关键对照：补丁的影响为零

**用未打补丁的产物跑同一门禁，结果完全相同**：

```
打补丁：   ws-a-v3 4.256%/3.545839% (168730/140563)  未登记 6
未打补丁： ws-a-v3 4.256%/3.545839% (168730/140563)  未登记 6
```

**原因**：v3 运行时是独立窗口/webview，**门禁只采到主页面**——
v3 那两屏的 DOM 里只有 `workbench-shell` 与拖拽热区，**没有任何 v3 运行时内容**。

**所以 `<title>` 在界面上看不看得见，门禁回答不了；但补丁对门禁的影响可以确定为零。**

## 三、结论与待办

1. **`<title>` 补丁：对门禁无影响（已对照实测）**，记账时写「层 1、`patches-v3.mjs`、
   验证方式=未打补丁/打补丁两次运行结果一致」。
2. **v3 两屏要过门禁，还需要两件事**（都不属于本次改动）：
   - 给这两屏补品牌遮罩（或把品牌 `aria-label` 纳入 `MASK_INTENTIONAL`）；
   - 查 shell 里那个缺失的 `img`（参照有、我们没有）。
3. **4.0.4 正式跟进时**，必须把 reference-version.json、锁文件、tgz、preload、
   protocol、gateway、MCP、门禁基线**一起**切 —— 版本一致性检查会挡住半升级。
