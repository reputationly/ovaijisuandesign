## 1. 怎么映射的

判据按可信度从高到低：

1. **声明名**（最硬）。还原时顶层声明名是保留的，只去掉了 rollup 加的 `$2` 冲突后缀；
   所以 bundle 里的 `foo` 应该能在我们的源码里找到同名声明的文件。
2. **锚点**。`data-action-ui-id` / 翻译键 / 接口路径 / 事件名，按 IDF 加权
   （只出现在一两个文件里的锚点权重高，到处都有的权重接近 0）。
3. 都没有 → **无归属**，按区域分组列在第 4 节，不猜。

置信度：**声明名是最硬的判据**（还原时顶层声明名保留），所以——

- `high`：声明名只命中一个文件；或者撞了多个文件但锚点把它定了下来；
- `medium`：声明名撞了多个文件、锚点也没偏向（取了命中名最多的那个）；或者没有声明名、只有够强的锚点；
- `low`：只有单个弱锚点。

## 2. 映射自检

拿 3.0.21 里**已知是应用代码**的语句（按仓库既有的归类结果）当标尺，
用同一套判据去挂，看能挂上多少 —— 这个命中率是第 3 节那张表的**覆盖率**（有没有漏），
「有没有挂错」由紧随其后的精确率回答。

- 已知应用语句 7,601 条，挂上 7,194 条，**命中率 94.7%**
- 其中 high 6,166 / medium 1,028 / low 0

没挂上的那部分主要是没有顶层声明名、也没有功能面锚点的语句（内联表达式、匿名初始化）。

注意这是**覆盖率**不是准确率：它证明「该找到的都找得到」，不证明「找到的是对的」。

**歧义**：挂上的语句里，声明名只命中一个文件的有 1,970 条（直接可信），
名字撞了多个文件的有 406 条，其中 14 条靠锚点定下来，
剩下的取了「命中名最多」的那个，读表时按 medium 看待。

**精确率**：光算命中率只能证明「覆盖到」，所以另做一步——挂上的语句里凡是带字面量的，
就检查那个字面量是否真的出现在目标文件里。这是「挂对了」的直接证据。

- 抽查 1,426 条，字面量确实在目标文件里的有 1,342 条，**精确率 94.1%**

人工复核过三条「没对上」的，结论都是**映射本身是对的**，对不上的是判据：
`AudioLightbox` 确实在 `asset-center-panel.jsx` 里、`exportCroppedVideo` 确实在 `aac-trim-export.js` 里、
`SelectTrigger` 确实在 `select-content.jsx` 里；少数几条对不上是因为上游把那句文案改了
（例如 `Invalid crop range` 在我们的源码里已经不存在）。所以下面的比例是**保守下界**。

没对上的样例（逐个核对前不要当成挂错）：

- `added` `assets/asset-center-panel.jsx`：`canvas.audio-lightbox.download` `canvas.audio-lightbox.show-in-folder` `canvas.lightbox.downloadCurrent`
- `added` `assets/image-lightbox.jsx`：`canvas.image-lightbox.download` `canvas.image-lightbox.set-primary` `canvas.image-lightbox.show-in-folder`
- `added` `generation/select-content.jsx`：`aria-controls` `aria-expanded` `aria-haspopup`
- `added` `generation/select-content.jsx`：`aria-selected` `selectedIndex`
- `added` `chat/message-turn.jsx`：`M1.5 1.5L6.5 6.5M6.5 1.5L1.5 6.5` `Remove attachment` `a11y.removeAttachment`
- `added` `canvas/canvas-view-controls.jsx`：`absolute right-1 top-1 h-1.5 w-1.5 rounded-full`
- `added` `infra/base-ui.js`：`floatingRootContext` `isOpenedByTrigger` `isTriggerActive`
- `added` `infra/base-ui.js`：`data-base-ui-slider-control`

**新版这边的「应用 / 第三方」是近似判定**：第三方库的源码缓存已不在仓库里，
没法对新 bundle 重跑同一个分类器，只能用 3.0.21 归类出的第三方名字表来排除。
结果是：老库的新版本会被正确排除，**全新的第三方包会被误判成应用代码**，落进「判不了 / 无归属」两栏。
