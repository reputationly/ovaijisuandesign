## 三十五、第 173 轮：区间取回工具就绪，但**踩到了「连续块切片」的坑**

### 做了什么

`scripts/v3preload/extract-segments.mjs`：按 `closure-manifest.json` 里每项的
`start`/`end`（**AST 字节偏移**，不是行号）取回。

### 第一个错误：按「最小到最大」连续块切

第一版把一段里所有 todo 项的 `min(start)`–`max(end)` 当成一个连续块切。
结果把**中间已还原项的函数体**也切了进来：

```
      const subscriptionId = `task-${crypto.randomUUID()}`;
      ...
✘ Expected ";" but found "task"
```

`createTaskSubscriptionNegotiation` 在 `workspace-structure-events.js` 里已还原，
manifest 标成 `restored` 被过滤掉，但它在 bundle 里的**函数体**落在连续块中间。

**这正是用户提醒过的「切片差一行」类损坏。**

### 修法：逐项拼接

```js
const code = todo.map((x) => bundle.slice(x.start, x.end)).join("\n\n");
```

改完后 10 段全部可单独解析，合并成 1,568 行。

### 第二个发现：整段取回会带进 97 个邻居

按「连续区间整段」取时，段里有 **166 个顶层声明**，闭包只覆盖 69 个 ——
多出的 97 个是邻居，其中还包括本该用 npm 替换的 `BASE_62_DIGITS`。

**所以「整段取回」不能真的整段**，必须**按清单逐项取、但保持 bundle 顺序**。
改成逐项后：1,568 行、57 个外部依赖（19 个树里已有、38 个仍缺），
与闭包的 48 todo 基本吻合。
