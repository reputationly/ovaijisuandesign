## 五、卡住的地方（需要决策或换办法）

### 1. P3 剩下的 59 个「同一实体」不能逐名字归并

实测：任何一次跨文件搬名字都会在 `model ↔ project-resource-tags`、
`model ↔ frame-services`、`ui-components ↔ frame-services` 之间造出 import 环。
`check-tdz` 的 R3 每次都能抓到（本轮抓到 4 个，已全部回退）。

**唯一可行路径**：把这些互相咬合的模块**合并**（像第 141 轮合并
`canvas-v3-document` + `canvas-v3-client` 那样）。需要的合并组：

```
canvas-v3-model  +  project-resource-tags
canvas-v3-model  +  frame-services
ui-components    +  frame-services
frame-services   +  page-storage
```

### 2. P4 的 v3 门禁屏录不出来

`ws-a-v3` 在 `OV_UI=reference`（4.0.0 原版）与 `OV_UI=recovered`（我们的）下
**都超时**于 `waitForWorkspaceChatReady` —— v3 工作台本身还只渲染加载占位。

**顺序依赖**：接线 → 能录屏；录屏 → 才能验证。而接线的前置是 P2/P3 完成。

### 3. P2-1 的 vendor 剩余部分

按名字能识别的只有 187 条；按行号区间估算有 1137 条。
函数体哈希对 npm 语料的命中率只有 5–15%（产物是另一份构建）。

**需要**：以 bundle 行号区间为准的划分表（`toplevel-4.0.0.json` 已有行号，缺区间边界）。
