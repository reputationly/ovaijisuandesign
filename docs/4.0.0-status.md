## 十六、第 151 轮：找到「画布一接线聊天就挂」的真正原因 —— **TDZ 链**

### 诊断方法（有效的二分）

在 `WorkspaceV3Workbench` 里放**只加载不渲染**的探针：

| 探针 | 内容 | 结果 |

| A | `await import("canvas-area-v3.js")` 后返回 `() => null` | **仍然超时** |

**只 import 不渲染就已经挂** → 不是渲染问题，是**模块求值期副作用**。

| 探针 | 内容 | 结果 |
|---|---|---|
| D | `try { await import(...) } catch (e) { console.error(e) }` | 抓到真实错误 |

```
ERR [v3-probe] ReferenceError: Cannot access 'CANVAS_V3_TEXT_GENERATION_ROUTES$1' before initialization
```

### 根因：一串 TDZ

`canvas-area-v3.js` 在求值期就会碰到**声明在使用之后**的 `const/let`：

| # | 符号 | 位置 |
|---|---|---|
| 1 | `CANVAS_V3_TEXT_GENERATION_ROUTES` | `frame-services.js` 1963 声明、1199 使用 |
| 2 | `powers` | `canvas-v3-model.js` 5708 声明、5534 的 `increment()` 使用 |
| 3 | `Context$3` | `ui-components.js` 9089 声明、2541 使用 |
| 4 | `TableFullscreen$1` | 11166 声明、5150 使用 |
| 5 | `IMAGE_TOOLS` | 35720 声明、11159 展开使用 |

**每修一个，错误就前进一个** —— 说明这是一条链。

### 修好的部分（已验证）

- TDZ #1 修好后：`ws-a-v3` **6.242% → 5.500%**
- TDZ #2/#3/#4 修好后仍是 5.500%，但错误前进到了 #5

### 顺带发现的一个真实缺陷
