# 首页噪声定位与修复（第 2039 轮）

## 结论：不是卡片重挂，是「海报图 ↔ 视频」的切换时序

### 探针观测（纯 DOM，`PROBE_HOME=1` 注入，不改产品代码）

三次 `ONLY=home` 的观测结果完全一致：

```
卡片数演变：0 → 6 → 14 → 18 → 22（单调递增，**从未下降**）
aria-busy： 258ms 之后不再是 true，此后一直稳定
grid 身份： 仅早期变过一次（g1 → g2），之后不变
采集前 img 状态：总 2 / 已加载 2 / 待加载 0 / **视频 22 个**
```

**所以 A（loading 来回切）、B（selectedPrimaryId 变化重挂）、C（卡片 key 变化）
都不是原因** —— 这些都在前 260ms 内结束，此后结构完全稳定。

真正的原因：**每张卡片先挂一张海报 `<img>`（就是那些 `showcase-assets` 请求），
`<video>` 的 `readyState` 够了之后海报被移除。采集时还剩几张海报，完全取决于视频就绪时序。**

这解释了两件事：
1. 22 次 `showcase-assets` 请求（22 张海报）而采集时只剩 2 个 `<img>`
2. 0.035~0.054pp 的像素抖动（残留海报数量不同 → 卡片区域像素不同）

## 修法（只改门禁）

`SETTLE` 里加：等 `article.home-media-showcase-card video` 全部
`readyState >= 2`（最多 8 秒），然后 `pause()` 并把 `currentTime` 归零。

这样每次采集都发生在海报已统一移除、视频停在首帧的状态。

## 验证

| 阶段 | home 5 次波动 |
|---|---|
| 修复前 | **0.0544pp** |
| 修复后 | **0.0033pp**（14.7756 ×4，14.7723 ×1） |

`home-skill` / `home-skill-inspiration` 修复后 **5/5 完全相同**。

**已达到「与其余 34 屏同水平（≤0.012pp）」的目标。**

## 仍有一个偶发离群值

另有一批 5 次里出现过 1 次明显偏离（像素计数 641969 vs 662628，约 1.6pp）。
推测是那一次 8 秒等待超时、部分卡片仍是海报。

**若要彻底消除**：把等待上限提高，或在超时后记一条警告（当前是静默继续）。
建议后者 —— 让"没等到"变成可见信号，而不是一个悄悄发生的离群值。
