| 本仓库桌面版本 | 仍是 30.21.7。不要为了对齐去改版本号，除非任务明确要求 |

`main.js` 没有混淆，能直接读出类名、路由装饰器和函数体。用 Python `read_bytes()` 再去掉空字节后解码。`rg` 会因为空字节把文件当成二进制，搜不到。

```bash
/opt/homebrew/bin/python3.14 - << 'PY'
from pathlib import Path
data = Path("/Applications/MiniMax Design.app/Contents/Resources/gateway/dist/main.js").read_bytes().replace(b"\x00", b"")
text = data.decode("utf-8", "replace")
i = text.find("要找的函数或路径")
print(text[i:i+2000])
PY
```

系统自带的 `python3` 是 3.9，跑不了路由脚本里的 `list[str] | None`。固定用 `/opt/homebrew/bin/python3.14`。

## 2. 还原步骤

一次只做一块渲染层已经在调用、或清单上还缺的本地行为。做完就验收，再做下一块。

1. **对清单。** 打开 `docs/gateway-api.md`，找行首没有 `✓`、而且属于第 0 节「本地产品面」的路由。再用渲染层搜这个路径，确认调用形状（query、body、返回字段）。

   ```bash
   rg -n "/api/asset-center" app/renderer/src
   ```

2. **从发行包读行为。** 按第 1 节的方式抽出控制器方法、服务函数、SQL 和错误码。要抄的是判断、状态码、字段名和失败时的处理，不是把整段编译结果贴进仓库。

3. **写进现有模块。** 新代码放在已有目录旁边，例如资产中心就是 `app/gateway/src/asset-center/`。控制器路径用字符串字面量，这样路由脚本能扫到。注释用中文，只写为什么。新注释里不要写「官方」「official」「MiniMax」。

4. **沿用已经定下的本地替身，不要改回云端账号。**

   - 主体 id 是字符串 `"workspace"`，没有云端用户 id。
   - 代理身份看请求头 `x-hilo-agent-caller`，用环境变量 `HILO_AGENT_CALLER_KEY` 做 sha256 和时间安全比较。
   - v3 是否开启看 `HILO_PROJECT_ARCHITECTURE=resource_v3`，再加上 `HILO_GATEWAY_ROLE=workspace` 和 `WORKSPACE_DIR`。本地很多路由用这个判断，而不是登录态。
   - 资产中心库在 `HILO_ASSET_CENTER_DIR`，否则在应用数据根 `.asset-center`。只读时库不存在就当空库；第一次写入才建库。`library-status` 用来区分「没用过」和「建了但是空的」。
   - 生成水印默认开着。图片在临时文件上叠右下角，再发布进工作区。语音和音乐在末尾接提示音。失败只记日志，原来的文件留下。
   - 对话模型调用记录由 opencode 插件在响应头带有 trace id 时 `POST /api/chat/model-traces`。不要在缺少 `call_id` / `trace_id` / `status_code` 时编一条记录。

5. **补 e2e，放在改动的目录里。** 断言状态码、关键字段和副作用（文件出现或消失、画布节点、使用次数）。用发行包里的错误码和文案，例如 `entity_not_found`、`invalid_request`。

6. **跑第 4 节的验收。** 路由有增删时重新生成 `docs/gateway-api.md`。生成文档里本来就有「官方」「MiniMax」这几个词，那是脚本写的，不要手改那份清单去躲这些词。

7. **不要提交，除非用户明确说提交。** 工作区里还有别人改过、和这次还原无关的文件（opencode 配置、模型目录、maas-media、cool-music-video、聊天、技能文案）。不要把它们混进这次改动，也不要还原它们。

## 3. 写代码时已经踩过的坑

- gateway 测试必须在 `app/gateway` 里跑 `pnpm exec vitest`。仓库根目录的 vitest 会在注入 `TrashBufferService` 时失败。
- Node 用 fnm 的默认版本：`export PATH="$HOME/.local/share/fnm/aliases/default/bin:$PATH"`。
- 类型检查：`cd app/gateway && pnpm exec tsc --noEmit -p tsconfig.json`。
- 不要在 `@Injectable()` 和 `class` 之间插常量，TypeScript 会报 TS1206。常量放在装饰器上面。
- 控制器里的异步方法必须 `await`。漏掉时失败会变成 HTTP 500，而不是业务错误码。
- supertest 的 `.send()` 要 `await`，或者 `.end(cb)`。不这样，请求不会发出去。
- `tasks.ts` 和 `generation-runner.service.ts` 不能互相静态 import。停任务用动态 `import()` 加 `ModuleRef.get(..., { strict: false })`。
- 不要为了拿到 `WorkspaceProjectArchitectureService` 去让 `GenerateModule` 导入 `CanvasV3Module`，曾经因此起不来。任务服务里直接读环境变量。
- 资源版本只查相对路径时，不要去 join 还没建的 `resource_document_versions`。
- ffmpeg 临时文件的扩展名必须留在末尾（`.partial-name.mp4`）。`name.mp4.partial` 封装会失败。
- SQLite 的 `UNIQUE` 把多个 `NULL` 当成不同的行。要测冲突就显式传 `input_index: 0`。
- 不要在 sandbox 里跑会重建 `node_modules` 的 `pnpm install --filter`。上次中断后目录被清掉，要用 `pnpm install --config.confirmModulesPurge=false` 并且关掉 sandbox 才能装回来。
- gateway 依赖 `@ov/mcp-tools` 的字幕格式化。`dist/` 被 gitignore。本地测试前如果缺包，在 `app/mcp-tools` 里 `pnpm exec tsc -p tsconfig.build.json`。CI 的 turbo 会先构建依赖。
- 本机没有 `yt-dlp`。测试用 `YTDLP_PATH` 指一个假的可执行文件。不要自动下载那个二进制。
- 资产中心拖到画布只对旧画布。`HILO_PROJECT_ARCHITECTURE=resource_v3` 时返回 403，码是 `LEGACY_CANVAS_DISABLED`。
- 两个以上的附件拖上画布后，子节点坐标是相对分组的。分组原点才是请求里的 `position`。

## 4. 验收

每一块都要过下面三项。缺一项就不算这块做完。

### 4.1 类型

```bash
export PATH="$HOME/.local/share/fnm/aliases/default/bin:$PATH"
cd app/gateway
pnpm exec tsc --noEmit -p tsconfig.json
```

改了 `app/packages/opencode-plugin-hilo` 时，在那个包里再跑一次 `pnpm exec tsc --noEmit -p tsconfig.json`。

### 4.2 行为测试

只跑这次改到的 e2e，确认断言覆盖了成功路径和清单里写过的失败路径（400 / 404 / 409）。

```bash
export PATH="$HOME/.local/share/fnm/aliases/default/bin:$PATH"
cd app/gateway
pnpm exec vitest run src/asset-center/asset-center.e2e.test.ts
```

资产中心现有用例已经覆盖：空库、建实体、从本地文件入库、封面、搜索、挂工作区文件、材质化链接、拆链接、拖到画布成组、删除后列表消失。改这块时整份文件都要再跑过。

插件包的测试在 `app/packages/opencode-plugin-hilo`：`pnpm exec vitest run src/model-trace-capture.test.ts`。

### 4.3 路由清单

装饰器有增删时重跑。数字必须和终端最后一行一致，并且新路由在 `docs/gateway-api.md` 里是 `✓`。

```bash
/opt/homebrew/bin/python3.14 scripts/extract-gateway-routes.py --out docs/gateway-api.md
```

上次成功输出是：`557 条路由（我们 363 条）`。

`✓` 只表示方法名和路径字符串对上了，不表示响应形状对上了。响应形状靠 e2e 对着发行包里的字段和错误码。

### 4.4 什么算这块完成

- 渲染层已经依赖的字段都在（名字、状态码、错误码、文件是否出现）。
- 失败路径和发行包一致：缺参数 400，不存在 404，冲突 409。不要用 500 代替。
- 库还没建时，资产中心列表仍是 `{ entities: [] }`，`library-status` 仍是 `{ initialized: false }`。`src/cloud-config/cloud-config.e2e.test.ts` 里名为「资产中心」的用例锁着这件事。
- 没有把发行包的 `main.js`、`app.asar`、`phone.js` 以外的压缩包再提交进仓库。`phone.js` 是已知的未还原文件，不要再复制一份新的压缩脚本进来。

## 5. 下一块建议

资产中心的导出和导入。渲染层已经在用：

- `GET /api/asset-center/entities/:eid/export`，下载单个 zip。
- `GET /api/asset-center/entities-export?ids=`，一个外壳 zip，里面是多份可以单独再导入的 zip。
- `POST /api/asset-center/import`，multipart 字段名 `file`。`mode` 查询参数：`create-new`（默认）、`overwrite`、`copy`。

发行包里的包格式：zip 里有 `<名字>/manifest.json`，`version` 是 `"1.0"`，附件在 `attachments/<ord>_<文件名>`。没有附件的实体导出要 400，码 `export_no_attachments`。`create-new` 撞上还活着的同一实体 id 要 409，码 `import_entity_conflict`。`copy` 忽略 id，重名变成 `原名_2`。

gateway 现在没有 `archiver` / `yauzl` 依赖。用 Node 的 `zlib`（`deflateRaw` / `inflateRaw` / `crc32`）写一个小的 zip 读写即可，不要为了这一块新增依赖，也不要把压缩后的发行包嵌进来。

验收：导出再导入一轮，说明和附件字节还在；重复导入得到 409；`copy` 得到新 id 和新名字；没有附件时导出是 400。然后跑第 4 节，清单应从 363 增加到加上这几条路由。
