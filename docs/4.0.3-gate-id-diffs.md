# 门禁未通过屏的差异性质（第 122 轮核实）

## 结论：7 屏失败**全部是 `data-action-ui-id` 登记差异**，不是布局/配色

门禁把"登记元素集合"的差异算作失败，分两种：

- `dom.refOnly` —— **参照有、我们没有**（少登记了元素）
- `dom.oursOnly` —— **我们有、参照没有**（多登记了元素）

两者都不涉及像素，但都会让该屏判为"未通过"。这也解释了为什么这 7 屏的像素差异
（1.3% ~ 5.2%）与"未通过"并不完全对应：**它们是两类不同的判据**。

## 已核实的三屏（逐条列出 id）

### skills-mine（37 条，全是 oursOnly）
```
skills-mine-more-3d-animation-short-generator
skills-mine-more-anime-game-pv
skills-mine-more-blen...（共 37 个，形如 skills-mine-more-<skill.name>）
```
来源：`app/renderer/src/skills/my-skills/my-skills-view.jsx:192`
```
data-action-ui-id={`skills-mine-more-${skill.name}`}
```
**参照 bundle 里搜 `skills-mine-more-` 为 0 命中** —— 参照上这个"更多操作"按钮没有登记 id。
所以这一屏的 37 条是**我们多登记的**，不是少做了什么。

### skills-connectors（8 条）
```
refOnly: connectors-category-all, connectors-category-data-research,
         plugins-primary-tabs, plugins-tab-community, p...
oursOnly: connector-origin, connectors-sort
```

### ws-text-editor（10 条）
```
refOnly: canvas-text-close, canvas.file-node.rename-from-preview,
         canvas.file-node.view-card-from-preview, canvas.t...
oursOnly: canvas.node-promote-to-asset
```

## 怎么推进（下一步）

1. `refOnly` 的：到参照里找到该 id 所在的元素，在我们的对应组件上补同样的 id
2. `oursOnly` 的：两种选择
   - 若参照确实没有该元素 → 说明我们多了个 UI 元素（需核对是否 4.0.3 删掉了它）
   - 若参照有该元素但没登记 id → 我们保留 id（自动化需要），**把它登进白名单**
     （门禁支持白名单，前面各轮用它处理"已知且合理"的差异）

## 注意

这批差异**不影响渲染**，也不影响功能。它们反映的是"可自动化定位的元素集合"不同。
若要清掉，优先走"补登记 / 加白名单"，而不是删掉我们已有的 id ——
后者会让自动化测试失去定位手段。
