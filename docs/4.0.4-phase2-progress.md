### 门禁修复（`561051bd`）

v3 门禁连续三次在第一屏网络空闲超时：`/api/v1/home/showcase-assets/*.jpeg` 一直 pending。
根因是首页路由 `awaitShowcaseWarm()` 等预热，而对比模式缓存为空时预热要等 peer 锁并逐张从 CDN
拉封面，实测被拖到 40 秒。现在 `OV_UI` 下直接从包内 `assets/home-showcase/media` 复制；
生产路径不变。

## 主界面冲突现状

`apply-delta` 报 43 处冲突，`merge-conflicts` token 级 dry-run 只能自动合 3 条，且实际写回的一条
（`useCanvasV3PickerMedia`）产生了 `[owner,owner]`、无空格 `||` 和无人传的 `paused` 参数，已回退。
结论：**这批冲突不能靠自动合并**，原因是：

1. **chunk 哈希 import**：我们的源码树已把 `./GlobalSearchDialog-XXXX.js` 映射成真实模块路径，
   4.0.4 仍是带哈希的懒加载 import；这类“冲突”应保留我们的写法；
2. **还原桩**：`ensurePersistenceOwner`、`text$a/keys$1` 等是按旧产物补的兼容实现，4.0.4 同名声明
   是另一个函数；直接换会改语义；
3. **4.0.4 组件重构**：`DebugPanelDialog` 从 643 行拆成多个小卡片（`LogLevelCard` 已单独补）；
4. **纯性能埋点**：`createCanvasV3Client`、`CanvasV3Image` 等差异主要是 `recordPerfSpan`。

目前真正需要继续处理的是第 3、4 类里涉及功能和可见行为的部分，其余保留本地实现并记录原因。
