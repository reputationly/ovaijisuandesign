## 一、外部 Agent 接入 —— **本地功能，可做**

### 实现事实（已核实）

主进程 `out/main/chunks/index-C5sfBOaZ.js`：

```js
const EXTERNAL_AGENT_GRANT_DEFAULTS = {
  enabled: false,
  port: 18810,
  creditReminder: { enabled: true, threshold: 2e3 },
  allowedProjectPaths: [],
};
```

- 在本机起一个 MCP 服务，默认端口 **18810**，**默认关闭**
- 用 `allowedProjectPaths` 做项目白名单
- 由主进程拉起 `mcp-tools-v3/dist/external-main.js`（`EXTERNAL_MAIN_RELATIVE`）
- `isChildMessage` 里看得到 `external-agent:` 前缀的消息通道
- **该 chunk 里没有任何云端地址与外部 Agent 相关**；里面的 `https://accounts.feishu.cn` /
  `api.telegram.org` 等是飞书 / Lark / Telegram 的 IM 集成，属于另一套功能

### 需要处理的范围外部分

| 项 | 处理 |
|---|---|
| `creditReminder`（积分提醒，threshold 2000） | **去掉**。属计费，按规则不做 |
| `identity.getToken()` → "Sign in before accessing project assets" | 换成本地身份。这条在 4.0.0 的 v3 项目查询里就有，我们已处理过同类问题 |

### 要做的话

1. 主进程：外部 Agent 服务（端口、项目白名单、重启策略）
2. mcp-tools：加一个 HTTP 传输入口（相当于 `external-main.js`）
3. 设置页界面（**不含积分提醒**）
4. gateway：对应接口改本地身份

### 更正记录

我最初把 `config/external-api.loader.js` 当作「外部 Agent 依赖云端」的证据，**这是错的**：

- 那 4 个开放平台地址（`openplatform-test.xaminim.com` 等）是**通用外部 API / 用户管理**的基础地址，
  与外部 Agent 无关；"external" 指的是"外部 API"，不是"外部 Agent"。
- 该模块**在 4.0.0 里就已存在**，也不在 4.0.3 新增的 15 个模块里。
- 我们的 gateway 早已把这类云端配置换成了自己的平台。

**所以若决定不做外部 Agent，登记理由必须写「产品决定不开放本机 MCP 端口给外部 Agent」，
不能写「依赖云端」——后者与代码事实不符。**

## 二、下一步提示建议 —— **本地功能，可做**

模块：`gateway/dist/next-prompt-suggestion/{controller,service,suggestion-prompt}.js`
接口：`GET /api/sessions/:id/next-prompt-suggestion`

服务段内实测：**无** hailuo / api.minimax 云端地址、**无** credit 相关。

内容是纯提示词：`SUGGESTION_INSTRUCTIONS` 让模型「以用户口吻起草下一条消息」，
`SUGGESTION_MAX_CHARS = 60`、`SUGGESTION_MAX_OUTPUT_TOKENS = 2048`，
生成结果显示在输入框里当 ghost text。

**可以接我们自己的平台模型，不牵涉范围外内容。**
