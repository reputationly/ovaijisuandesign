## 二、必须知道的四件事

1. **基准版本**：`~/ov-golden-ref` 是 4.0.0，拿它比 4.0.3 会得出相反结论。
2. **搜参照要搜全部 chunk**：`assets/` 下有 358 个懒加载 chunk（共 720 个文本文件），
   只搜主 bundle 会误判「参照没有」。用 `node scripts/refdiff/refgrep.mjs <字符串>`。
3. **`*.dom.json` 是扁平列表**（`parentIndex` 全为 None）：
   不能用父子关系做分析，只能用**节点顺序**（`difflib.SequenceMatcher` 对齐）。
4. **动手前先确认「是不是已经有了」**：
   本会话有 5 次「以为是缺功能、其实只是没登记 id / 被挡住 / 接错组件」。

## 六、本会话最大的教训

**同一个问题我连续猜错 4~6 次**（`canvas.node-promote-to-asset`、
以及两次把 `.hilo` 复位误判为缺基线根因）。

**共同点：在「看起来很有道理」的推断上就写结论，而没有先做一次能证伪它的实测。**

**后来改成「用探针取真实数据 + 逐个来源排除」之后，
`showcase-assets` 那个悬案 9 轮就定案了——每一轮都推翻或收窄上一步，没有同义反复。**

**所以：能实测就不要推断；要推断就先写清「什么证据能推翻它」。**
