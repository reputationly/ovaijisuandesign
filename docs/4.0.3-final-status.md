## 第 2029~2047 轮：Playwright 探针带来的两个实质答案

装了 `playwright-core`（不下载浏览器，用仓库自带 Electron），
写了 `.probe/pw/probe.mjs`，支持 `PROBE_UI=recovered|reference` 分别在两侧跑同一套检查。

### 答案 1：首页封面请求（此前是悬案）

| 指标 | 我方 recovered | 参照 reference |
|---|---|---|
| `route` 拦 `showcase-assets` 命中 | **22** | **0** |
| `/api/plugins` 响应体 | `{"plugins":[]}` | `{"plugins":[]}` |

- **`route` 能拦住这些请求** → 「拦不住」是门禁侧 `Fetch`/`setBlockedURLs` 的用法问题
- **参照根本不发这些请求** → 22 次全来自我方
- 进一步定位：`showcase-assets` 路径在参照里 0 命中；两侧都读
  `home_tabs_showcase_config`，但**我方从该配置取 `showcase-assets` 图片地址，参照不取**
  → **同一个配置键、消费字段不同**，这很可能也是首页 14.72% 里封面差异的来源

### 答案 2：`skills-connectors` 卡 loading 的真因

探针读到 `/api/plugins` 返回 **`{"plugins":[]}`**（200 但为空），
而参照那屏是失败态（`page-state-error-retry`）——**两侧停在不同终止状态，属环境不对称**。
同时查出我方原本会**永远停在 loading**（三处根因：`catalogLoading` 误判 /
`prime()` 空返回 / 云端 Promise 挂住），**已修**。

### 探针用法

```bash
cd .probe/pw
PROBE_UI=recovered node probe.mjs   # 我方
PROBE_UI=reference node probe.mjs   # 4.0.3 参照
# 产物：out/probe-recovered.json / out/probe-reference.json
```
