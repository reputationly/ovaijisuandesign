## 五、困难（按影响排序）

### 1. 三方合并对本增量的自动率极低
`apply-delta` 的纪律是「只有我们这一条还等于 4.0.0 的原文才自动替换」。我们的源码命名、分文件都自己做过，
所以**3142 条提案自动替换 0 处、冲突 3362 条**。改用 token 级合并后能自动解决一部分，但仍有 133 条要人工。

### 2. 合并器按「声明名」配对，同名会配错
实测：133 条冲突里**约 45% 不是真改**——4.0.0 与 4.0.3 的原文逐字相同，只是同名声明在 bundle 里出现多次，配到了另一条。
已加三级过滤（已应用 / 上游未改 / 需新符号），把清单从「283」收敛到「37 可直接应用 + 90 需新符号」。

### 3. 新组件是硬门槛
4.0.3 新增 266 个顶层声明（组件类 71、常量 66、其他 129）。**不移植这些，对应语句就合不进来**。
最大的就是 `MediaReveal` + LQIP 子系统。

### 4. token 合并会产出「语法合法但语义错误」的代码
实例：`expectedCurrentVersionId: source.versionId` 被合并成裸 `versionId`，还留下重复键。
所以「语法检查 + 自由标识符检查」两道不够，必须叠加 `audit-v3`（重复声明）与门禁冒烟。
**因此我改成「逐条看参照两版差异再手工应用」**，不再整批 `--apply`。

### 5. 我们的源码与参照已不可逐字对应
- 三份协议镜像（协议包 / preload / 渲染层 model）——改一处要同步三处，容易漏；
- 渲染层和 gateway 的模块划分与参照不同（884 个 gateway 模块里只有 86 个能按路径对上）。

### 6. 工具链的两个坑（已修，但会重复踩）
- **尖括号被吃掉**：源码里的 `/ thinking…/` 被当成 HTML 标签过滤，落盘成没有 `<` 的版本，导致功能静默失效。
  已改用 `\u003c` 转义写法。
- **测试读的是 `dist` 不是 `src`**：gateway 的 `.js` 后缀解析到 `dist/`，改了源码不重建，测试仍跑旧代码。
  已把「改完先 `npm run build` 再跑测试」写进流程。

### 7. 门禁的「像素差异」还不能当预算用
37 屏的差异组成尚未逐项解释，所以 `residual-budget.json` 里 36 屏是 `pending`（回归护栏，**不是预算**），
1 屏是 `invalid`（`ws-layout` 两边不是同一状态）。要变成「预算」，得先把每屏差异拆到可解释为止。

### 8. gateway e2e 有环境性偶发
「真实工作区」那批 e2e 每次跑失败的用例都不同（403/404/500），重跑即过。值得单独查，但不阻塞功能。

## 六、如果继续，建议的顺序

1. **移植 `MediaReveal` + LQIP 子系统** —— 一次解决 90 条里大约 1/3（16 + 11 处引用）
2. **逐条清 37 条「不引入新符号」** —— 已核对 8 条、6 条早做过，剩下的按参照逐条对

4. **渲染层 ghost text 接线** —— 端点已就绪，只差界面
5. 最后再谈「残差预算转 ok」—— 需要先把每屏差异拆解清楚
