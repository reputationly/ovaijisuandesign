## 0. 范围确认（2026-10-24，负责人已定）

三项都跟。这一节同时改正上一版报告里两处定性错误。

1. **`code-project` 全部跟。** 本地 gateway 5 条路由，`CodePublishService` 把产物交给本地
   `delivery.deliver(...)`（`DeliveryController`，`api/v3/deliveries`，4.0.3 已有、我们也已实现），
   落到 Resources，不往外发；MCP 的 4 个 `code_*` 工具一起跟，`project_rules` 并入 `memory`。
   **运行时已查（2026-10-24）**：MCP 侧 `probeCodeEnvironment` 只探测系统 PATH 上的 node / npm / python3 / git；
   ffmpeg 先看 `FFMPEG_PATH`，没有才退回 PATH。我们主进程已经把自带 ffmpeg/ffprobe 写入
   `app/desktop/src/main/index.ts` 的 gateway 环境，所以打包不需要再新增 node/python 运行时；
   node/python 缺失时按参照的语义报 `available: false` 即可。
2. **调试日志级别全跟，只去掉遥测。** 设置界面、`logLevel` IPC、`logLevelOverride` 持久化、
   `POST /api/logs/request-level` 都跟。**上一版把 `request-level` 说成「远端运维触发日志收集」是错的**：
   它只接受本机请求（非 loopback 一律 403），只往心跳队列塞一条 `set_log_level`，主进程下次心跳取走，
   临时切换本地日志级别（默认 24 小时），**不收集、不上传任何日志**。我们的 gateway 已有
   `heartbeat.module.ts` 的 `enqueueCommand`，跟进成本是 1 条路由 + 主进程 1 个指令分支。
   **不跟的只有 `LOG_LEVEL_CHANGE`**：参照走 `trackEvent` 上报，我们主进程没有 `trackEvent`；
   日志级别变化只写本地日志。
3. **24 个观测事件照搬。** **上一版说「没有网络上报」不准确**：参照主界面会把这些 measurement 订阅后
   经 `reportRumAction` 送进 RUM（至少有 `canvas_v3:selection`、`canvas_v3:zoom`）。我们的
   `reportRumAction`（`app/renderer/src/i18n/init-rum.js`）只在本地内存记状态、不发出，
   所以照搬不会让数据离开本机。RUM 停用（`ov-changes.md` #10）继续保持。

**全量门禁耗时已查（2026-10-24）**：不是 4.0.4 引入的。历史两次全量
（`.probe/ui-compare/2026-10-24T00-47-41-845Z`、`2026-10-24T01-38-15-416Z`）都是 18.0–18.1 分钟，
本次去掉上传入口后也是 18.1 分钟；文档里的「约 16 分钟」已过时。13/37 屏触发 `stableShot` 的 8 次重拍上限，
这是主要成本（文本光标、交互后动画是候选，尚未逐屏定位）。阶段 3 换基线前继续盯住 10 分钟闲置挂起边界。
