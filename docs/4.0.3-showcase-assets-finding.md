# 首页封面请求（showcase-assets）：答案

## 问题（此前未解）

> 首页封面请求用 `setBlockedURLs` 和 `Fetch` 都拦不住，到现在还不知道请求是从哪里发出去的。

## 答案（第 2046 轮，用 Playwright `route` 分别在两侧实测）

用同一个探针，分别以 `PROBE_UI=recovered`（我方界面）与 `PROBE_UI=reference`（4.0.3 参照界面）启动应用：

| 指标 | 我方（recovered） | 参照（reference） |
|---|---|---|
| `route` 拦 `/api/v1/home/showcase-assets/**` 命中数 | **r1=4 / r2=8 / home=22** | **0 / 0 / 0** |
| 请求总数（skills-connectors） | 70 / 68 | 90 / 85 |
| `/api/plugins` 响应体 | `{"plugins":[]}` | `{"plugins":[]}` |

**结论有两条：**

1. **`route` 确实能拦住这些请求** —— 所以「拦不住」是门禁侧
   （`Fetch` + `setBlockedURLs`）的用法问题，不是请求来自别处。
2. **参照界面根本不发这些请求** —— 22 次命中全部来自我方。

**也就是说：`showcase-assets` 是我方多出来的请求，4.0.3 的首页没有它。**

这与门禁里看到的 `net::ERR_ABORTED`（8 条，全部是 showcase-assets）对得上：
我方先发起、随后又被取消，而参照连发起都没有。

```bash
cd .probe/pw

PROBE_UI=reference node probe.mjs   # 4.0.3 参照
# 产物：out/probe-recovered.json / out/probe-reference.json
```
